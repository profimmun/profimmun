# Платформа — онлайн-школа

Полноценная платформа онлайн-обучения (аналог GetCourse, где вся платформа —
это одна школа). Frontend и backend на **Next.js 16**, база данных **PostgreSQL**,
ORM **Prisma**. Дизайн — современный минимализм со светлой и тёмной темой.

## Возможности

**Аутентификация**
- Регистрация, вход, выход
- Восстановление пароля по email (сброс по ссылке с токеном)
- Сессии в БД + httpOnly cookie, хеширование паролей (bcrypt)
- Роли: администратор и студент

**Клиентская часть (студент)**
- Каталог курсов (весь сайт за авторизацией, публичного лендинга нет)
- Страница курса с программой и записью на курс
- Личный кабинет с прогрессом обучения
- Плеер урока: видео (YouTube / Vimeo / загруженный файл) + текстовый контент (Markdown)
- Прохождение тестов с автоматической и ручной проверкой

**Админ-панель**
- Дашборд со статистикой школы и графиками (записи по дням, топ курсов)
- Конструктор курсов: модули, уроки, публикация, обложка
- Редактор урока: видео (ссылка или загрузка файла) + контент
- Конструктор тестов: вопросы с **закрытыми** (один/несколько вариантов) и
  **открытыми** ответами
- Проверка открытых ответов вручную с выставлением баллов
- Управление пользователями и ролями

## Быстрый старт

Нужен **Node.js 20+** и строка подключения к **PostgreSQL**. Docker не требуется:
подойдёт бесплатная база на [neon.tech](https://neon.tech) — одну и ту же можно
использовать и локально, и на Vercel.

### 1. Установка зависимостей
```bash
npm install
```

### 2. Переменные окружения
Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL` и `DIRECT_URL`.
Остальное для локального запуска можно оставить как есть.

### 3. База данных и демо-данные
```bash
npm run db:deploy
```
```bash
npm run db:seed
```

### 4. Запуск
```bash
npm run dev
```
Откройте <http://localhost:3000>.

## Развёртывание на Vercel

Платформа готова к деплою: сборка сама генерирует Prisma Client, а загрузка
файлов переключается на Blob-хранилище.

**1. Создайте базу PostgreSQL.** Vercel Postgres, [Neon](https://neon.tech) или
Supabase. Понадобятся две строки: пулированная (`DATABASE_URL`) и прямая
(`DIRECT_URL`, для миграций).

**2. Создайте Blob-хранилище.** В панели проекта: *Storage → Blob*. Vercel сам
добавит `BLOB_READ_WRITE_TOKEN` в переменные окружения. Без него загрузка
обложек и видео работать не будет — файловая система на Vercel только для чтения.

**3. Импортируйте репозиторий** в Vercel. Фреймворк определится автоматически,
команды сборки менять не нужно.

**4. Задайте переменные окружения** (*Settings → Environment Variables*):

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `DATABASE_URL` | да | Пулированное подключение к PostgreSQL |
| `DIRECT_URL` | да | Прямое подключение (для миграций) |
| `AUTH_SECRET` | да | Длинная случайная строка: `openssl rand -base64 32` |
| `BLOB_READ_WRITE_TOKEN` | да | Добавляется автоматически при создании Blob |
| `NEXT_PUBLIC_APP_URL` | желательно | Ваш домен, напр. `https://school.ru` |
| `SMTP_*` | нет | Без них письма сброса пароля пишутся в лог |

**5. Создайте администратора.** Миграции применяются автоматически при сборке,
поэтому таблицы уже готовы. Осталась одна учётка — временно подставьте
продакшен-строку в локальный `.env` и выполните:

```bash
ADMIN_EMAIL=you@mail.ru ADMIN_PASSWORD='СложныйПароль123' npm run db:admin
```

> Не используйте `npm run db:seed` в продакшене: он создаёт демо-аккаунты с
> общеизвестным паролем `password123`. Это только для локальной разработки.

### Что важно знать про Vercel

- **Файловая система эфемерна.** Поэтому SQLite не используется, а загрузки идут
  в Blob. Локально (без `BLOB_READ_WRITE_TOKEN`) файлы по-прежнему пишутся в
  `public/uploads` — разработка не требует облака.
- **Ограничение частоты запросов хранится в памяти процесса.** На нескольких
  серверлесс-инстансах у каждого будет свой счётчик, поэтому защита от подбора
  паролей ослабевает. Для нагруженного продакшена вынесите хранилище в Upstash
  Redis — интерфейс `hit()` / `reset()` в `src/lib/rate-limit.ts` менять не нужно.
- **Загрузка видео ограничена размером запроса.** На Hobby-плане это 4.5 МБ, на
  Pro — больше. Для больших файлов используйте ссылки на YouTube/Vimeo — они
  поддерживаются в редакторе урока.

## Полезные команды

| Команда              | Действие                                  |
| -------------------- | ----------------------------------------- |
| `npm run dev`        | Запуск в режиме разработки                 |

| `npm run db:migrate` | Создать новую миграцию при правке схемы    |

| `npm run db:studio`  | Prisma Studio (визуальный редактор БД)     |

## Структура проекта

```
prisma/
  schema.prisma          # модель данных
  seed.ts                # демо-данные
  migrations/            # SQL-миграции
src/
  app/
    (auth)/              # вход, регистрация, сброс пароля
    (site)/              # каталог курсов, кабинет студента
    learn/               # прохождение курса (плеер уроков, тесты)
    admin/               # админ-панель
    api/upload/          # загрузка видео/обложек
  components/
    ui/                  # базовые UI-компоненты
    admin/               # компоненты админки
    learn/               # компоненты обучения
    auth/                # формы аутентификации
  lib/                   # prisma, auth, actions, утилиты
```

## Заметки по разработке
- Загруженные файлы: локально — в `public/uploads` (в git не попадают), на
  Vercel — в Blob-хранилище. Переключение автоматическое, по наличию
  `BLOB_READ_WRITE_TOKEN`.
- Доступ к курсам: по умолчанию курс открыт всем студентам сразу после
  регистрации. Ограничить можно галочкой «Доступ только для групп».
- Видео можно как загружать файлом, так и вставлять ссылкой на YouTube/Vimeo.
- Контент уроков поддерживает Markdown (заголовки, списки, ссылки, код, цитаты).
- Первый администратор создаётся сид-скриптом; далее роли меняются в разделе
  «Студенты» админ-панели.
